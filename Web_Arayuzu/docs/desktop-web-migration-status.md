## Scope and evidence

The migration target is the web-compatible UI and workflows in the AYEC Pro desktop application. This record tracks verified slices and open work; a passing focused test is not proof of whole-application parity.

The current static inventory command is `python Web_Arayuzu/tools/desktop_web_gap_audit.py`. Its latest run reports 43 desktop page names and 43 matching web labels, 106 desktop dialog definitions, 178 setting keys, and 1,401 desktop Qt signal connection calls. These are inventory counts, not parity proofs. A local Ollama qwen3:4b classification request for the 50 KB desktop contracts page timed out after 180 seconds; its follow-up used a narrow rg-first source scan. A second focused qwen3:4b classification request for the global-search snippets timed out after 120 seconds; the follow-up scanned only the named search class, handler, navigation routes, and result logic. For the loan-payment slice, qwen2.5-coder:7b classified the Python dialog as below 80% and the web mapping as above 80%; its rationale reflected programming-language stereotypes instead of defect evidence, so the label was treated only as triage and the specific loan route and calculation symbols were checked directly. The stock-locations route retains its detailed page heading and uses the desktop navigation label.

Fresh inventory on 2026-10-15 reports 43/43 desktop page labels with none missing, a web dialog catalog, 178 desktop setting keys and 161 web keys with no missing keys, and the three native-only printer settings (`print_document_printer`, `print_label_printer`, `print_receipt_printer`). The inventory also records 334 web dialog signal calls and 1,401 desktop Qt signal connections. These counts do not verify every workflow or visual state. A focused `rg` scan found no remaining `window.confirm`, `window.prompt`, or `window.alert` calls in `Web_Arayuzu/web`; printer selection and direct printer access remain native-only.
